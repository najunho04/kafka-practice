연속 구간 commit과 commit 메타데이터

파티션 0의 offset 40~51을 key A·B·C가 병렬로 처리합니다. 같은 key는 한 번에 1건씩만 실행되고(KEY 순서), 끝나는 순서는 offset 순서와 다릅니다. 슬라이더를 움직이거나 ▶ 재생을 눌러 시간(tick)을 흘려 보세요.

tick 0 / 12
완료 + commit됨 완료했지만 commit 못 함 (앞에 안 끝난 건이 있음) 처리 중 대기 중

① 파티션 0의 레코드 (숫자 = offset, 글자 = key)

commit 위치 = "빈틈 없이 끝난 구간의 끝+1". 앞에 안 끝난 offset이 하나라도 있으면 그 뒤가 끝났어도 거기서 멈춥니다.

② 워커 (key마다 동시에 1건)

③ 브로커의 __consumer_offsets 에 저장되는 commit 기록

metadata 칸은 선택 사항입니다. Parallel Consumer 같은 라이브러리는 여기에 "연속 구간 뒤에 먼저 끝난 offset"을 압축해서 넣습니다. (우리 구현은 offset 숫자만 commit)

④ 지금 이 순간 크래시가 나면? (commit/close 없이 강제 종료 → 재시작)

* metadata에는 크기 한도가 있고(기본 4096바이트) commit 시점과 어긋날 수도 있어서, 중복을 줄이는 최선의 장치일 뿐 0을 보장하지는 않습니다. 그래서 멱등 컨슈머는 여전히 필요합니다.
